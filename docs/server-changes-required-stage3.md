# Требуемые изменения серверного API для этапа 3

Документ составлен после сверки с серверными `docs/client-api.md`,
`docs/architecture.md`, реализацией `POST /api/v1/activate` и её тестами.
Серверный проект не изменялся.

## Уже реализовано на сервере

- `POST /api/v1/activate` принимает JSON `{"activation_key":"<12 цифр>"}`.
- Формат проверяется как ровно 12 десятичных цифр.
- Успешный ответ содержит `account` и секретные профили `wireguard`,
  `amneziawg`, `vless` и заголовок `Cache-Control: no-store`.
- Неактивный, истёкший, неполный и неизвестный аккаунты получают одинаковый
  `401 Invalid activation key`.
- Повторные неуспешные попытки ограничиваются ответом `429`.

## Чего не хватает клиенту

1. В успешном ответе активации отсутствует объект подписки. Нужны минимум:
   `status` (`active`, `expired`, `suspended`), `expires_at`, `plan_name`,
   `device_limit`, `verified_at`.
2. Нет клиентского метода обновления аккаунта/подписки после первоначальной
   активации. Нужен аутентифицированный `GET /api/v1/account` либо эквивалентный
   endpoint с тем же объектом подписки.
3. Серверная модель не различает отдельное состояние подписки `suspended`.
   Нужно определить его доменную семантику и переходы отдельно от `expired` и
   полного отзыва аккаунта.
4. Текущий общий `401` намеренно не раскрывает причину отказа и поэтому не может
   быть источником UI-состояний `expired`/`suspended`. Эти состояния следует
   возвращать только уже аутентифицированной клиентской сессии, не ослабляя
   защиту endpoint активации от перебора ключей.
5. Если будет введён непрозрачный session/access token, нужны его срок действия,
   ротация и endpoint отзыва (`POST /api/v1/logout`). До появления такого токена
   клиентский выход остаётся локальной очисткой защищённого хранилища.
6. Нужна опубликованная типизированная схема ответа и стабильный код/формат
   ошибок для `401`, `429` и временных `5xx`. Секретные ответы должны сохранять
   `Cache-Control: no-store`.

До согласования этих изменений клиент использует только `MockActivationApiClient`
и не обращается к production API.
