# Настройки и mock VPN-адаптеры (этап 5)

## Разделение движков

Созданы независимые ports `WireGuardAdapter`, `AmneziaWgAdapter` и
`XrayRealityAdapter`, объединённые минимальным `VpnProtocolAdapter`.
`MockVpnEngine` выбирает адаптер по типизированному `VpnProtocol`; полный профиль
и произвольные команды через интерфейс не передаются.

Все текущие адаптеры являются mock и симулируют только start/stop. Их capability
model явно возвращает `false` для системного kill switch, DNS, реакции на смену
сети и сна.

## Настройки

Работают сохраняемые в OS-backed storage настройки выбора
автоматического/ручного протокола и сервера по умолчанию. Выход из аккаунта не
удаляет эти несекретные предпочтения. Выбор протокола применяется экраном серверов при следующем
создании подключения; несовместимый ручной выбор безопасно откатывается к
первому протоколу выбранного сервера.

Следующие элементы существуют в capability-aware UI, но отключены у текущего
mock/runtime:

- kill switch и DNS;
- автоматическое подключение;
- переподключение после смены сети;
- поведение после сна;
- автозапуск приложения;
- сворачивание после подключения.

Они автоматически могут стать доступны только после внедрения адаптера,
который явно объявляет соответствующую возможность. Одного отображения toggle
недостаточно.

Перед реальной интеграцией обязательны
[`../security/vpn-engine-threat-model.md`](../security/vpn-engine-threat-model.md)
и [`windows-privileged-service.md`](windows-privileged-service.md).
