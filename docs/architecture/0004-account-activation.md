# Аккаунт, ключ и подписка (этап 3)

## Границы реализации

Экран аккаунта использует `AccountRepository`, который координирует строго
типизированный `ActivationApiClient` и `SecureStorage`. В текущем этапе API —
детерминированный mock; production URL и HTTP-адаптер не добавлены.

```text
AccountScreen
    |
    v
AccountRepository
    |------------------------|
    v                        v
ActivationApiClient      SecureStorage
(mock in stage 3)        (OS-backed adapter)
```

`ActivationKey` принимает только 12 цифр, маскирует `toString()` и не
используется в сообщениях об ошибках. API-ошибки представлены безопасным enum,
не содержащим тело запроса или ключ.

## Хранение и выход

Windows-сборка использует `flutter_secure_storage`. Плагин шифрует значения
AES-GCM, а ключ шифрования хранит через Windows Credential Manager. В тестах
используется только `InMemorySecureStorage`.

После активации ключ, локальная сессия и каждый VPN-профиль записываются в
защищённое хранилище. Обычное восстановление UI читает только несекретную
метаинформацию и маску; полный ключ читается только после кнопки показа или
копирования. Выход сначала пытается остановить активное mock-подключение, затем
удаляет ключ, сессию и VPN-профили независимо от результата остановки, не
затрагивая несвязанные настройки приложения.

## Контракт сервера

Существующий endpoint не возвращает сведения о подписке. Необходимые изменения
зафиксированы отдельно в [`../server-changes-required-stage3.md`](../server-changes-required-stage3.md).
