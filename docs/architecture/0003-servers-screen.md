# Экран «Серверы» (этап 2)

## Область этапа

Экран работает только с `MockApiClient`, `MockServerRepository` и
`MockVpnEngine`. Он не открывает системный туннель, не меняет маршруты или DNS,
не вызывает production API и не выполняет оплату.

Реализованы каталог стран и серверов, поиск, сортировка, избранное,
рекомендация, ping, доступность, выбор протокола, панель подключения, время и
счётчики трафика. Текущий сервер по умолчанию — `Армения / Yerevan S1`.

## Поток данных

```text
ServersScreen
  ├─ ServerRepository ── ApiClient ── /mock/v1/servers[/ping]
  └─ VpnEngine ── MockVpnEngine ── connection states + statistics
```

UI зависит только от доменных ports. Замена mock-адаптеров будущими
production-реализациями не должна менять экран или переносить в него
привилегированную логику.

## Состояния подключения

Покрыты все значения `VpnConnectionPhase`: `disconnected`, `validating`,
`connecting`, `connected`, `reconnecting`, `disconnecting`,
`blockedBySubscription`, `noNetwork`, `serverUnavailable` и `error`.

Пользователю показываются заранее определённые безопасные сообщения. Внутренние
`errorCode`, исключения, адреса и параметры профиля в UI не выводятся.

## Тестовый каталог и production-граница

Армения входит в обычный mock-каталог. Дополнительные страны служат только для
проверки будущего многосерверного интерфейса и помечены как тестовые.

Они включаются в debug/profile запуске только с
`KENAI_ENABLE_TEST_SERVERS=true`. В release одновременно действуют две защиты:

1. `bootstrap.dart` игнорирует флаг при `kReleaseMode`.
2. Compile-time guard `dart.vm.product` закрывает и каталог, и mock ping; AOT
   tree-shaking поэтому не включает имена и идентификаторы тестовых серверов.

## Проверки

- unit-тесты фильтрации, сортировки, избранного, ping и переходов mock FSM;
- widget-тесты каталога, панели сервера, протокола, доступности, трафика и всех
  пользовательских состояний;
- release-сборка с намеренно переданным dev-флагом и бинарный поиск тестовых
  идентификаторов.
