# Логи и диагностика (этап 6)

## Поток данных и границы

```text
приложение / VPN-адаптер / служба / сеть
                 |
          DiagnosticLogger.log
                 |
       SecretRedactor (обязательно)
                 |
       JSONL текущего пользователя
                 |
        повторная редакция
          /             \
      экран          ZIP-архив
                         |
               явное действие пользователя
                         |
                    Downloads
```

UI и остальные модули получают только `DiagnosticLogger`; прямой доступ к
`DiagnosticLogStore` не передаётся через `AppDependencies`. Это не позволяет
обычному коду приложения обойти центральную границу редакции. Перед чтением для
UI и перед ZIP-экспортом выполняется дополнительная редакция как защита от
повреждённых или созданных старой версией записей.

## Категории

- приложение;
- WireGuard;
- AmneziaWG;
- Xray;
- системная служба;
- сеть.

Запись содержит время UTC, категорию, уровень, стабильный код, безопасное
сообщение и структурированные поля. Фильтрация выполняется по категории, уровню
и тексту. Краткий отчёт содержит только количества событий, предупреждений,
ошибок и распределение по категориям.

## Redaction pipeline

`SecretRedactor` рекурсивно обрабатывает строки, maps и списки. Он удаляет:

- 12-значные ключи активации, включая разделённые пробелами или дефисами;
- приватные ключи и поля с VPN-реквизитами;
- полные WireGuard/Xray-конфигурации и `vless://` URI;
- UUID;
- bearer/access/refresh tokens;
- cookies, пароли, credentials и secrets;
- `Authorization`, `Proxy-Authorization`, `Cookie` и `Set-Cookie`.

Значение заменяется на `[REDACTED]`; полная конфигурация — на
`[REDACTED VPN CONFIGURATION]`. Исходное значение после вызова logger не
сохраняется.

## Хранение и экспорт

Windows-клиент хранит редактированные JSONL-записи в профиле текущего
пользователя: `%LOCALAPPDATA%/Kenai VPN/logs/client.jsonl`. GUI не требует прав
администратора. Повреждённые строки пропускаются и не выводятся пользователю.

ZIP создаётся без временного файла и содержит `logs.jsonl` и `report.json`.
Имя архива формируется приложением и проверяется allow-list выражением; путь из
логов или вызывающего модуля не принимается. Только после подтверждения в UI
архив записывается в `Downloads` пользователя.

Автоматическая отправка, загрузка на сервер и фоновый экспорт отсутствуют.

## Проверки безопасности

Тесты намеренно передают logger тестовые ключи, приватные ключи, UUID, токены,
cookies, пароли, заголовки и конфигурации. Затем они отдельно проверяют сырой
JSONL-файл, данные экрана и байты ZIP. Ни одно исходное значение не должно
присутствовать ни в одной границе.
